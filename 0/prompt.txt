WHY

- But our message bodies are 100% templates. They ignored supplier questions like "which volume can you commit to?" about 35 times, and "which figures is that based on?" (P05, P03).
- Trait detection uses regexes on the exact practice-note phrasing. On Sunday a new data release arrives, and the Live Final uses unseen suppliers, so the regexes will silently miss new wording.

SCOPE, in priority order
1. LLM trait extraction (highest transfer value).
   - From supplier notes, letters and replies, return [{trait, quote}], e.g. wants_fast_payment, cash_short, capacity_idle, pricing_committee, multi_year_preference.
   - Validate that every quote appears verbatim in the source; otherwise drop it.
   - Merge the result with the regex traits. It's interpretation only.
   - Opt-in config field: model_traits.
2. LLM option choice.
   - Code computes 2–4 legal, code-priced candidate packages per turn (existing ones: hold, payment trade, chargeback/value swap, standard step).
   - The LLM reads the thread and returns the index of the package to send, plus a one-line reason.
   - Fallback is today's deterministic choice.
   - It never invents a package, price or term.
   - Opt-in field: model_choice.
3. LLM-worded reply to supplier questions.
   - When the supplier asks a direct question (volume, figures, forecast, committee), the LLM writes 1–3 sentences answering it, using only facts from an allowlist the code provides: fixed volume, verified claim IDs/values, contract terms.
   - A validator rejects the text if any number or claim isn't in the allowlist, or if it mentions internal estimates, reservations or targets. On rejection, fall back to the template.
   - Opt-in field: model_answers.
