## 1. What v5 is

`configs/score-push-v5.json` / `configs/score-push-v5-run.json` = `score-push-v4` +

```json
"fixed_volume_types": ["raw_material"],
"anchor_by_type": {"raw_material": 0.19},
"rounds_by_type": {"raw_material": 10}
```

v5 minus these three keys is key-for-key equal to v4. Everything below is gated on `fixed_volume_types`, so
the other eight practice cases run v4's code paths unchanged (section 3).

Behaviour on a `raw_material` case (P08 70710, P18 70740), all deterministic:

| final offer | **accept at once** (`final_accept_safe`; gain × 0.75 < loss × 0.25) | — | — |

Code (commit 38970af):
- `src/negotiator/fixed_volume.py` (from the breakthrough branch) + new `ladder()` / `next_claim()`: the claim queue
  above, each series once, PO only below the standing ask, nothing after a final; all claims pass `claims.verify`.
  The supplier's hedge sentence is deliberately *not* applied (unlike `recent_index_claims`): the arena verifies the
  public series regardless and 70710 still moved on them (S6, S16, and v5-p08-s1 below).
- `PackageAgent._fixed_volume` (hook after `_bundle_volume`, before `_fast_payment_note` / `_cost_breakdown_request`)
  adds paragraph/attachment/claim; `_enrich_evidence` returns early for fixed_volume types (the ladder owns claims).
- `decide_thread`: for fixed_volume types the price steps equally from the anchor towards the supplier's **opening**
  price (`rounds_by_type` = ladder length 10 ⇒ ≈+0.115/round), floored by the default k/5 convergence toward its
  current ask, capped at its current ask. Reason: the default schedule re-targets the supplier's latest price, so
  when it concedes fast our step collapses (sim with rounds 8: +0.09 then **+0.02**; S4 showed a token move draws a
  final). Worst case (supplier holds at 5.70 for ever): we reach its price at our 5th sheet → ≤6 supplier replies,
  inside an 8-minute wave even at 60 s per reply; the `play_case` deadline fallback remains behind that.
- `tools/fixed_volume_sim.py`: offline ladder check against the S6 (P08) and S9 (P18) supplier replies.
- Tests: `tests/test_fixed_volume.py` 9 (ladder order, `next_claim` gating, P08/P18 end-to-end sim with a final,
  hold-at-5.70 time budget). Full suite **810 passed** (`uv run --locked pytest -q`, ARENA_DATA set); ruff clean.

Merge notes: conflicts only in `agent.py` (hook order) and `policy.py` (list validator tuple; kept
`value_swap_types`, `fast_payment_types`, `fixed_volume_types`). `cli.py` is main's (`conditional_exchange=False`
with a policy config). The sentence "This is a conditional exchange: we can commit to this package in return for
the proposed unit price." in P08/P18 bodies is the *trades* package wording of the measured v3/v4 path
(`_offer`, `package_types`), present in v4 as well; untouched for byte-identity on the other package cases.
