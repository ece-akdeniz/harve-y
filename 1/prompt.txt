# Harvey Negotiation Intelligence Lab — Overview Redesign

## Summary

Reframe the current workspace as Harvey’s **Negotiation Intelligence Lab**: a calm, editorial “intelligence desk” that makes value, risk, and the next review action obvious at a glance. Preserve the orange Harvey brand, but prioritize evidence-led decision making over a generic dashboard.

The deployed workspace is implemented on `origin/codex/supplier-workspace-20261011`, not the current detached checkout. Primary UI files are `tacto-negotiator/src/negotiator/lab/static/workspace.{html,css,js}`, with `supplier-brief.js`, `knowledge.js`, and `lab/workspace.py` providing the supporting views/data.

## Key changes

- Rebuild the overview around one focal “decision brief”:
  - headline simulated value;
  - clear explanation of its evidence basis;
  - one ranked “review next” negotiation with reason, supplier, status, and direct entry point.
- Replace the four equal-weight metrics with a hierarchy:
  - primary value/coverage signal;
  - compact operational strip for active sessions, supplier coverage, and attention count;
  - clarify when metrics are unavailable or not comparable.
- Turn “Needs attention” into a prioritized triage queue, using explicit reason labels such as timeout, stale runner, failed requirement, or unresolved decision.
- Turn “Recent supplier activity” into a concise evidence stream: supplier, case, last meaningful event, outcome/state, and timestamp—without duplicating triage items.
- Update top-level language to emphasize learning from completed negotiations, not merely storing them: “What we learned,” “Review next,” and “Evidence captured.”
- Establish reusable UI primitives—status tokens, badges, numeric formatting, row actions, empty/loading/error states—so Supplier and Shared Knowledge screens can inherit the design without a second visual system.
- Maintain existing routes, authentication, API contracts, environment selection, refresh behavior, and source-linked evidence; this is a presentation and interaction-hierarchy change, not a negotiation-policy change.

## Experience and implementation

- Use the selected **Intelligence desk** direction: warm off-white canvas, restrained charcoal type, Harvey orange reserved for value, urgency, current navigation, and primary actions.
- Use a desktop two-column overview beneath the value brief: triage on the left, evidence/activity on the right; collapse to a single ordered flow on mobile.
- Keep detail and raw evidence progressively disclosed. A user should reach a supplier/thread in one click, but not face full conversation data until they ask for it.
- Add keyboard-visible focus states, semantic headings and lists, live-status announcements, skeleton loading states, and clear no-data/error guidance.
- Validate the redesigned source against the existing responsive breakpoints and the Impeccable detector after implementation.

## Test plan

- Verify all overview states: populated data, no negotiations, no attention items, unavailable savings, stale/running sessions, API refresh failure, and narrow mobile layout.
- Confirm selecting a triage or activity item routes to the correct supplier negotiation and preserves the selected environment.
- Run the project’s relevant frontend/server tests plus a bounded desktop and mobile visual review.
- Confirm no API payload, authentication, supplier-detail, evidence, or environment-filter regressions.

## Assumptions

- The redesign begins on `origin/codex/supplier-workspace-20261011` or a branch containing those workspace files; it should not overwrite the current detached checkout’s unrelated runtime changes.
- “Simulated cost reduction” remains the approved headline value metric, with its existing calculation disclosure retained.
- Overview is the implementation scope for this pass; supplier and knowledge views receive only shared-token/component compatibility, not full redesigns yet.
